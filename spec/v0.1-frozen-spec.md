# AgentLens v0.1 Frozen Specification

Status: Frozen
Specification version: 0.1
Canonical schema version: "0.1"
Ingest protocol version: 1
HTTP API version: v1

---

## 0. Purpose

AgentLens v0.1 is a local-first open-source debugger for AI Agent execution.

The v0.1 product contract is:

When a supported AI Agent executes once, AgentLens captures its execution trace locally and allows the user to inspect LLM calls, tool calls, handoffs, errors, latency, and token usage in a browser.

This document freezes the contracts required to implement AgentLens v0.1.

Implementation Issues MUST NOT introduce design decisions that contradict this document.

When this document intentionally leaves a decision open, that decision is explicitly classified as Implementation Choice.

## 1. Normative language

The terms MUST, MUST NOT, SHOULD, SHOULD NOT, and MAY are normative.

* MUST / MUST NOT: required for v0.1 compatibility.
* SHOULD / SHOULD NOT: strong recommendation; deviation requires a concrete implementation reason.
* MAY: optional behavior that does not alter the contract.

## 3. Resolved design contradictions

This section records decisions where the earlier Design Plan left more than one valid interpretation.

### 3.1 Canonical IDs are not framework IDs

Framework-native IDs MUST NOT be used directly as AgentLens canonical IDs.

AgentLens generates its own canonical IDs.

Framework IDs are stored separately under source.

Reason:

* framework ID formats differ
* OpenTelemetry-compatible ID sizes are fixed
* canonical IDs must remain framework-independent

### 3.2 Span identity is (trace_id, span_id)

A canonical Span ID is 64-bit.

Therefore span_id alone MUST NOT be treated as the database identity.

The unique span identity is:

(trace_id, span_id)

Consequences:

PRIMARY KEY(trace_id, span_id)

and the detail endpoint is:

/api/v1/traces/{trace_id}/spans/{span_id}

There is no:

/api/v1/spans/{span_id}

endpoint in v0.1.

### 3.3 latency_ms is derived

latency_ms MUST NOT be part of the persisted Canonical Trace or Span.

It is calculated as:

ended_at - started_at

and is exposed by the Query API.

If ended_at == null, latency_ms == null.

### 3.4 Full snapshots are used for lifecycle events

trace.started, trace.ended, span.started, and span.ended contain full canonical entity snapshots.

They are not arbitrary patches.

A lifecycle event is a full Canonical snapshot in both structure and previously observed knowledge.

When producing a later lifecycle snapshot, the producer MUST carry forward previously observed Canonical facts according to the field-specific rules in §27 whenever the later source callback does not provide a newer explicit value.

The producer MAY retain the minimum previously normalized and sanitized Canonical state in memory for the active Span in order to construct the later full snapshot.

Such state MUST NOT contain unsanitized framework objects or credentials, MUST NOT be persisted to disk, and SHOULD be released when it is no longer required for that Span lifecycle.

This ephemeral per-Span state is not a persistent SDK spool.

This is required so that:

* events can arrive out of order
* *.ended can reconstruct an entity without having received *.started
* merge rules remain deterministic

### 3.5 Span I/O is the only source of truth for tool arguments/results

Tool input and result are represented as:

span.input
span.output

There are no duplicated:

tool_arguments
tool_result

fields.

details.tool contains tool identity only.

### 3.6 kind is not part of v0.1 Canonical Span

The earlier candidate kind = internal/client/server/... is removed.

It is not required by v0.1 and would primarily encode assumptions for future OpenTelemetry export.

A future OTel adapter may derive span kind when that feature is implemented.

### 3.7 SQLite does not duplicate details into LLM/tool source-of-truth tables

Canonical details is persisted once as details_json.

v0.1 does not maintain both:

details_json

and separately authoritative LLM/tool records.

This prevents inconsistent duplicate state.

SQLite JSON querying or application-layer aggregation is sufficient for local v0.1 workloads.

## 4. Architectural invariants

The following are v0.1 architectural invariants.

They MUST remain true for every Issue.

### INV-01 — Framework isolation

Framework integrations MUST convert framework objects into AgentLens Canonical objects before transport.

Forbidden dependency:

Collector → OpenAI Agents SDK

Allowed dependency:

OpenAI Agents SDK
    ↓
Adapter
    ↓
Canonical Schema

### INV-02 — Collector is framework-agnostic

The collector MUST NOT import or interpret OpenAI Agents SDK classes.

It only understands:

* AgentLens ingest protocol
* Canonical Trace
* Canonical Span

### INV-03 — Storage is hidden behind the backend

The Python SDK and frontend MUST NOT directly access SQLite.

### INV-04 — UI only consumes Query API

The React frontend MUST NOT know:

* SQLite layout
* OpenAI Agents SDK objects
* ingest event objects

### INV-05 — Agent execution has priority over tracing

AgentLens failure MUST NOT fail the user’s Agent execution.

This applies to:

* serialization failure
* queue overflow
* HTTP failure
* collector unavailable
* timeout
* invalid local collector response
* AgentLens callback failure

Tracing failures MAY be logged.

They MUST NOT propagate through the framework callback into Agent execution.

### INV-06 — AgentLens telemetry is OFF by default

Without explicit AgentLens enablement:

* no AgentLens transport worker starts
* no AgentLens HTTP requests occur
* no AgentLens trace data is persisted
* no AgentLens analytics or external telemetry is sent

### INV-07 — Content capture is independently OFF by default

Enabling AgentLens does not imply content capture.

Default:

enabled = false
capture_content = false

Typical explicit local use:

enabled = true
capture_content = false

Full local trace content requires:

enabled = true
capture_content = true

### INV-08 — Redaction happens before transport

Sensitive-data redaction MUST happen inside the SDK/integration process before an event enters the HTTP transport queue.

The collector MUST NOT be the first privacy boundary.

### INV-09 — No persistent SDK spool

The SDK transport queue is memory-only in v0.1.

Failed telemetry is not persisted to disk for later delivery.

### INV-10 — Canonical Schema is not OpenTelemetry Schema

OTel terminology MAY influence field design.

OTel field names and semantic conventions MUST NOT become the AgentLens persistence contract.

### INV-11 — Canonical schema is framework-independent

A field MUST NOT be added to the canonical core solely because one framework exposes it.

Framework-specific information belongs in:

source
attributes

unless it represents a canonical Agent concept.

### INV-12 — localhost only

The v0.1 server MUST bind to:

127.0.0.1

by default.

Official v0.1 startup documentation MUST NOT instruct users to expose the collector on:

0.0.0.0

No remote deployment security model is defined by v0.1.

## 5. Primitive types

### 5.1 CanonicalTimestamp

Wire timestamps MUST:

* be RFC 3339
* be UTC
* use Z
* contain no more than microsecond precision

Examples:

2026-08-10T13:00:00Z
2026-08-10T13:00:00.123456Z

Database timestamps are stored as integer microseconds since Unix epoch.

### 5.2 JSONValue

JSONValue means exactly one of:

null
boolean
finite number
string
array<JSONValue>
object<string, JSONValue>

The following are not valid canonical JSON values:

* NaN
* Infinity
* Python objects
* bytes
* datetime objects
* sets
* functions
* arbitrary class instances

Adapters MUST normalize source values into JSONValue before event creation.

### 5.3 JSONObject

object<string, JSONValue>

metadata and attributes MUST always be JSON objects, never null.

Empty value:

{}

## 6. Canonical identifiers

### 6.1 Trace ID

Canonical Trace ID:

^[0-9a-f]{32}$

Properties:

* 128-bit
* lowercase hexadecimal
* MUST NOT be all zeros
* generated by AgentLens
* SHOULD use cryptographically secure randomness

Example:

4bf92f3577b34da6a3ce929d0e0e4736

### 6.2 Span ID

Canonical Span ID:

^[0-9a-f]{16}$

Properties:

* 64-bit
* lowercase hexadecimal
* MUST NOT be all zeros
* generated by AgentLens
* meaningful only together with its trace ID

Example:

00f067aa0ba902b7

### 6.3 Event ID

Ingest event IDs MUST be RFC 4122 UUID strings.

v0.1 producers MUST generate UUIDv4 IDs.

Example:

4dbd9b3f-9c54-42ed-b0c0-529e99c35ca4

Retries MUST reuse the exact same event_id.

A retry MUST NOT generate a new ID.

## 7. Framework native ID contract

Framework-native IDs are persisted only for diagnostics/correlation.

They MUST NOT define canonical identity.

### 7.1 Trace source

{
  "framework": "openai-agents",
  "framework_version": "x.y.z",
  "integration": "openai_agents",
  "integration_version": "x.y.z",
  "native_trace_id": "trace_..."
}

Fields:

framework: string | null
framework_version: string | null
integration: string
integration_version: string
native_trace_id: string | null

### 7.2 Span source

framework: string | null
framework_version: string | null
integration: string
integration_version: string
native_trace_id: string | null
native_span_id: string | null
native_parent_span_id: string | null

### 7.3 Adapter mapping lifetime

A framework adapter MUST maintain in-process mappings:

native trace ID → canonical trace ID
(native trace ID, native span ID) → canonical span ID

Mapping MUST be stable for the lifetime of that trace.

Framework-native Span identity is:

(native_trace_id, native_span_id)

native_span_id alone MUST NOT be used as a process-global mapping key.

Parent preallocation uses:

(native_trace_id, native_parent_span_id)

Parent resolution MUST occur within the same native_trace_id scope.

Concurrent allocation for the same native identity pair MUST return the same canonical Span ID.

Different native identity pairs within the same native Trace MUST NOT map to the same canonical Span ID.

The mapping operation and unknown-parent preallocation operation each have one atomic result.

If a child references a native parent ID that has not yet been observed, the adapter MUST allocate and remember the canonical parent ID immediately.

Example:

child arrives first
native parent_123
    ↓
allocate canonical 42abcdef...
later parent_123 arrives
    ↓
reuse canonical 42abcdef...

This prevents broken parent relationships when framework callbacks are observed in an unexpected order.

Mappings do not need to survive process restart.

## 8. Canonical Trace Schema

Exact v0.1 structure:

{
  "schema_version": "0.1",
  "trace_id": "4bf92f3577b34da6a3ce929d0e0e4736",
  "name": "Agent workflow",
  "started_at": "2026-08-10T13:00:00.000000Z",
  "ended_at": null,
  "status": "unset",
  "source": {
    "framework": "openai-agents",
    "framework_version": "x.y.z",
    "integration": "openai_agents",
    "integration_version": "x.y.z",
    "native_trace_id": "trace_..."
  },
  "metadata": {},
  "attributes": {}
}

### 8.1 Fields

schema_version

Required.

Exact v0.1 value:

"0.1"

trace_id

Required canonical Trace ID.

name

Required non-empty string.

Maximum:

256 Unicode code points

started_at

Required.

ended_at

CanonicalTimestamp | null

status

Exact enum:

unset
ok
error

Semantics:

* unset: the top-level workflow outcome is not yet known, or the integration cannot observe that outcome
* ok: the producer has explicit evidence that the top-level workflow completed successfully
* error: the producer has explicit evidence of an unrecovered top-level workflow failure

Status transitions are terminal:

unset → ok
unset → error

Forbidden:

ok    → error
ok    → unset
error → ok
error → unset

The existence of a child Span whose status is error MUST NOT modify Trace.status.

A Trace MAY therefore have:

status = ok
error_count > 0

This represents a workflow that completed successfully while one or more child operations failed or were recovered.

Trace.status = ok does not assert semantic correctness of the Agent result.

source

Required TraceSource object.

metadata

User-defined context.

Must be {} when absent.

attributes

Integration / AgentLens-generated context.

Must be {} when absent.

User-facing manual APIs MUST NOT allow arbitrary mutation of reserved AgentLens attributes.

## 12. Content capture model

input and output are always present as fields.

Their presence as null alone does not indicate whether content was unavailable or deliberately omitted.

The accompanying capture object is authoritative.

### 12.1 CaptureInfo

state:
  captured
  not_captured
reason:
  null
  disabled
  source_unavailable
  not_yet_available
  size_limit
  serialization_error
redacted:
  boolean

### 12.2 Valid combinations

Captured:

{
  "state": "captured",
  "reason": null,
  "redacted": false
}

Captured with secrets removed:

{
  "state": "captured",
  "reason": null,
  "redacted": true
}

Disabled:

{
  "state": "not_captured",
  "reason": "disabled",
  "redacted": false
}

### 12.3 Captured JSON null

This is valid:

{
  "input": null,
  "capture": {
    "input": {
      "state": "captured",
      "reason": null,
      "redacted": false
    }
  }
}

It means the actual captured input value was JSON null.

This is different from:

state = not_captured

### 12.4 Content size limit

Each independently captured:

input
output

has a maximum canonical serialized size of:

262144 bytes

256 KiB.

The size is measured after sanitization using UTF-8 canonical JSON serialization.

If the limit is exceeded:

value = null
state = not_captured
reason = size_limit
redacted = false

v0.1 does not store partially truncated JSON.

### 12.5 CaptureInfo decision precedence

For each content field (input and output), CaptureInfo MUST be determined independently.

The producer MUST apply the following decision procedure in this exact order:

1. not_yet_available
2. disabled
3. source_unavailable
4. serialization_error
5. size_limit
6. captured

The first applicable condition is authoritative. Later conditions MUST NOT override an earlier condition.

#### 12.5.1 not_yet_available

Use:

state  = not_captured
reason = not_yet_available

when the lifecycle stage itself means that the value is not yet expected to exist.

For v0.1 this rule specifically applies to span.started output. Every span.started event MUST represent output as:

{
  "output": null,
  "capture": {
    "output": {
      "state": "not_captured",
      "reason": "not_yet_available",
      "redacted": false
    }
  }
}

This applies regardless of capture_content, whether the framework source exposes an output-like value, or whether the framework source omits output entirely. The adapter MUST NOT attempt to capture, serialize, or size-check span.started output.

#### 12.5.2 disabled

If not_yet_available does not apply and capture_content = false:

state  = not_captured
reason = disabled

This decision MUST be made before checking whether source content exists. When capture is disabled, AgentLens MUST NOT expose through CaptureInfo whether the underlying framework possessed that content.

#### 12.5.3 source_unavailable

If capture_content = true and the lifecycle stage permits the value to exist, but the framework/integration does not provide that value:

state  = not_captured
reason = source_unavailable

This includes fields deliberately omitted by the upstream framework's own privacy/tracing configuration. AgentLens MUST NOT fabricate or reconstruct missing source content.

#### 12.5.4 serialization_error

If capture is enabled, source content exists, the lifecycle stage permits capture, and AgentLens cannot normalize that source value into JSONValue:

value  = null
state  = not_captured
reason = serialization_error

A serialization failure MUST NOT cause Agent execution to fail.

#### 12.5.5 size_limit

If capture is enabled, source content exists, JSON normalization and sanitization succeed, and serialized sanitized content exceeds 262144 bytes:

value  = null
state  = not_captured
reason = size_limit

No partial JSON is stored.

#### 12.5.6 captured

Only when none of the previous conditions apply:

state  = captured
reason = null

The captured value MAY itself be JSON null. Redaction is represented independently using redacted = true | false.

## 13. Redaction semantics

Redaction runs regardless of:

capture_content

for any data that AgentLens persists or transports.

### 13.1 Redaction order

For content:

source value
↓
JSON normalization
↓
redaction
↓
size check
↓
canonical event
↓
queue

Secrets MUST NOT enter the transport queue in unredacted form.

### 13.2 Mandatory sensitive key names

Object keys are matched case-insensitively.

At minimum, the following keys MUST be treated as secret-bearing:

authorization
proxy-authorization
x-api-key
api-key
api_key
apikey
access_token
refresh_token
password
passwd
secret
client_secret
cookie
set-cookie

Their values MUST be replaced by:

"[REDACTED]"

The object key itself remains.

### 13.3 Authorization-like string values

Case-insensitive strings matching the conceptual form:

Bearer <credential>

MUST retain the scheme but redact the credential:

Bearer [REDACTED]

### 13.4 API-key safety

Adapters MUST NOT deliberately inspect, serialize, or copy framework API-key properties into:

* metadata
* attributes
* source
* errors
* input/output
* logging emitted by AgentLens

This includes OpenAI Agents SDK tracing API-key properties.

### 13.5 redacted flag

If at least one value inside an input/output tree is replaced by AgentLens redaction:

redacted = true

Otherwise:

redacted = false

### 13.6 Metadata and attributes

Metadata and attributes are also recursively sanitized.

They do not have a CaptureInfo.

Redacted values appear directly as:

"[REDACTED]"

### 13.7 Structured redaction and free-text sanitization are distinct

AgentLens v0.1 defines two independent sanitization mechanisms:

1. structured key redaction
2. free-text credential-pattern sanitization

Both occur before transport queue insertion. Neither mechanism claims to detect every possible secret.

#### 13.7.1 Structured key redaction

Structured key redaction applies recursively to JSON objects.

When an object key matches a mandatory sensitive key, its entire value is replaced with:

"[REDACTED]"

without inspecting the original value. The object key remains.

Structured key redaction applies recursively to input, output, metadata, attributes, and any other JSON object intentionally persisted by the Canonical contract.

#### 13.7.2 Free-text credential-pattern sanitization

Free-text sanitization operates on user/framework-derived string values after structured-key handling.

It MUST be applied at minimum to:

* error.message
* string leaves inside input
* string leaves inside output
* string leaves inside metadata
* string leaves inside attributes
* framework-derived human-readable names/details where they may contain arbitrary text

Canonical identifiers, enums, timestamps, and version fields are not treated as arbitrary free text.

#### 13.7.3 Bearer credentials

Case-insensitive text matching Bearer followed by a non-empty contiguous credential token MUST become:

Bearer [REDACTED]

#### 13.7.4 Basic credentials

Case-insensitive text matching Basic followed by a credential MUST become:

Basic [REDACTED]

#### 13.7.5 Credential assignments in free text

Case-insensitive credential names from the mandatory structured-key set, when appearing as an obvious scalar assignment using : or =, MUST have the assigned scalar value replaced.

Implementations MUST support both quoted and unquoted scalar credential values.

Examples include:

api_key=[REDACTED]
api-key: [REDACTED]
x-api-key: [REDACTED]
password=[REDACTED]
access_token = [REDACTED]
client_secret: [REDACTED]

#### 13.7.6 Sanitization guarantee boundary

AgentLens v0.1 guarantees sanitization of:

* values beneath the mandatory structured sensitive-key set
* Bearer credential patterns
* Basic credential patterns
* obvious free-text assignments using the mandatory credential names

AgentLens v0.1 explicitly DOES NOT guarantee detection of:

* arbitrary unknown secret formats
* credentials with no recognizable key or scheme
* application-specific secret formats
* encoded/encrypted secrets
* secrets embedded in arbitrary natural language
* all future provider-specific API-key formats

Documentation MUST NOT claim that arbitrary secrets are detectable with 100% reliability.

Users remain responsible for avoiding sensitive content capture when such content is not required. The primary privacy control remains capture_content = false by default.

## 24. Event idempotency

### 24.1 Event-content identity and hash material

Event idempotency is based on event_id plus normalized event content.

Normalized event content consists exactly of:

event_type
emitted_at
payload

For hashing only, emitted_at is parsed and converted to an integer number of microseconds since the Unix epoch in UTC.

Conceptual hash material is exactly:

{
  "event_type": "<validated event type>",
  "emitted_at_us": <integer>,
  "payload": <validated canonical payload>
}

Normalization rules:

1. event_type is the exact validated event-type string.
2. emitted_at is parsed as CanonicalTimestamp and converted to emitted_at_us.
3. Equivalent timestamp text representing the same microsecond instant produces the same emitted_at_us.
4. The original emitted_at text is not included in hash material.
5. payload is parsed and validated as the applicable Canonical Trace or Span.
6. JSON object key ordering and insignificant whitespace are irrelevant.
7. JSON numbers use the collector's deterministic finite-number canonical representation.
8. Normalized content is serialized as deterministic UTF-8 JSON.
9. SHA-256 is calculated over those bytes and stored as lowercase hexadecimal.

The following are NOT part of event-content hashing:

event_id
protocol_version
HTTP headers
batch position
HTTP request timing
collector receive time

The hash is an internal collector value. SDK producers MUST NOT be required to calculate it.

Therefore timestamps such as:

2026-08-10T13:00:00Z
2026-08-10T13:00:00.000000Z

produce identical timestamp hash material.

### 24.2 Retry contract

When retrying an event, the producer MUST reuse the same event_id and preserve the same event content after protocol normalization.

A retry MUST NOT change event_type, emitted_at, or payload. In particular, emitted_at MUST NOT be replaced with the retry time.

### 24.3 Exact Event ID retry

If an already-known event_id arrives and the incoming event_content_sha256 equals the stored event_content_sha256:

* it is an idempotent duplicate
* no entity state changes
* no timestamps are modified
* request remains successful
* the event contributes to duplicates

### 24.4 Event-ID conflict

If the same event_id arrives with a different event_content_sha256, the collector MUST return 409 Conflict with error code event_id_conflict. The entire ingest batch is rolled back.

### 24.5 Entity semantic equality is different from event idempotency

Event-content equality and entity semantic equality are separate concepts.

Event-content equality decides whether reuse of the same event_id is a valid retry. It includes event_type, emitted_at, and payload.

Entity semantic equality applies when separate events describe the same Trace/Span lifecycle snapshot. It ignores event_id and emitted_at but compares lifecycle stage/event type and Canonical entity payload, subject to collector-derived and field-specific merge exceptions in this specification.

Two events MAY have different event_id and emitted_at while describing the same semantic entity snapshot. Such events MAY be accepted as an equivalent entity no-op under repeated-start/repeated-end rules.

Reuse of the same event_id with a different emitted_at is an event_id_conflict even when the payloads are otherwise semantically identical.

The span.ended values are authoritative only after the producer has applied the full-snapshot completeness rules below and subject to the Span I/O collector merge rules below.

### 27.1 Span I/O observation-preserving merge

The full-snapshot event protocol remains unchanged.

These collector merge rules apply only to Span input, output, and their corresponding CaptureInfo objects.

Input authority is determined independently of event arrival order:

1. captured input from a valid span.started event
2. captured input from a valid span.ended event
3. the CaptureInfo/value pair from the highest available lifecycle stage

When both span.started and span.ended contain captured input, the span.started captured input is authoritative.

Different captured input representations between span.started and span.ended do not constitute entity_conflict. span.started is the canonical observation point for input supplied when the operation began; a later framework snapshot may expose a mutated, normalized, or richer representation of the same semantic input.

Different repeated span.started snapshots remain subject to the repeated-start entity_conflict rule.

For output:

* span.started.output MUST remain null with state = not_captured and reason = not_yet_available
* only span.ended may provide authoritative captured output
* a stale span.started event MUST NOT replace or remove output observed in span.ended
* different repeated span.ended output snapshots remain subject to the repeated-end entity_conflict rule

For both input and output:

* value and CaptureInfo are merged as one inseparable pair
* captured evidence MUST NOT be replaced by not_captured evidence
* captured JSON null remains captured evidence
* no event history or additional Canonical field is introduced

### 27.2 Non-I/O full-snapshot completeness

When producing span.ended, the producer MUST carry forward the following observations from its previously normalized and sanitized Canonical span.started state whenever the later source callback does not provide a newer explicit value:

metadata
attributes
details.provider
details.request_model
details.response_model
details.response_id
details.usage
details.finish_reasons
details.request_parameters
details.estimated_cost

The producer MAY retain the minimum previously normalized and sanitized Canonical state in memory for the active Span in order to construct the later full snapshot.

Such state MUST NOT contain unsanitized framework objects or credentials, MUST NOT be persisted to disk, and SHOULD be released when it is no longer required for that Span lifecycle.

This ephemeral per-Span state is not a persistent SDK spool.

Field-specific rules follow.

metadata and attributes:

* start from the previously observed Canonical object
* keys explicitly present in the later observation MAY add or update values
* a key absent from the later observation is retained
* an empty later object is not a deletion instruction
* v0.1 defines no lifecycle-snapshot deletion operation for metadata or attributes

details.provider, details.request_model, details.response_model, and details.response_id:

* null means unknown or unavailable
* a later null MUST NOT replace a previously observed non-null value
* a later explicit non-null value MAY replace an earlier value

details.usage:

* apply the rule independently to each usage counter
* null means unknown or unavailable
* a later null MUST NOT replace a previously observed integer, including zero
* a later explicit integer is the newer measurement and is authoritative

details.finish_reasons:

* a later non-empty array is authoritative
* an empty later array MUST NOT erase a previously observed non-empty array
* when no non-empty value has been observed, an empty array remains valid

details.request_parameters:

* null means unknown or unavailable
* a later null MUST NOT replace a previously observed JSONObject
* when both observations provide JSONObject values, start with the previously observed object and apply keys explicitly present in the later observation
* a missing key is not a deletion instruction
* a later explicit value, including JSON null, MAY update that key

details.estimated_cost:

* null means unknown or unavailable
* a later null MUST NOT replace a previously observed EstimatedCost
* a later explicit EstimatedCost is the newer estimate and is authoritative

After these producer rules are applied, the resulting span.ended snapshot is authoritative for these non-I/O fields.

After the first event is created:

* repeating an identical configuration is a no-op

### 31.1 Loopback endpoint requirement

Officially supported AgentLens v0.1 collector endpoints MUST be loopback-only.

Accepted endpoint requirements:

scheme = http
host   = localhost OR an IP literal whose address is loopback

configure calls and first-event creation have one observable total order.

The first successfully created AgentLens event atomically freezes the configuration snapshot used for that event.

A configure call linearized before that event affects it. After freeze, an identical configure call is a no-op and a differing call raises AgentLensConfigurationError.

Before freeze, multiple configure calls are applied in their linearized order; the last completed configuration before event creation is used.

## 34. agentlens.flush

Conceptual API:

flush(timeout_seconds: float = 2.0) -> bool

Returns:

true

if all events queued at call time have either:

* been delivered successfully, or
* reached a terminal non-retryable/drop result

before the deadline.

Returns:

false

if the deadline expires with queued/in-flight events remaining.

## 35. Transport queue semantics

### 35.1 Queue type

Bounded in-memory FIFO.

Maximum:

2048 events

Each enqueue attempt has exactly one atomic outcome:

accepted
or
dropped

An event is accepted only if, at the enqueue linearization point, shutdown has not closed event acceptance and the bounded queue has capacity.

An accepted event atomically reserves one internal FIFO position. Concurrent producer ordering is the order of these enqueue linearization points.

The internal FIFO position is not a Canonical field and is not persisted.

### 35.2 Callback behavior

Framework tracing callbacks MUST NOT perform synchronous collector HTTP calls.

Their critical path is:

framework callback
↓
canonical mapping
↓
privacy normalization/redaction
↓
non-blocking queue enqueue
↓
return

### 35.3 Queue full

If the queue is full:

drop the newly arriving event

The callback MUST NOT wait for space.

Existing queued events are retained.

Reason: keeping earlier lifecycle events produces visible incomplete traces rather than allowing instrumentation backpressure to affect Agent execution.

### 35.4 Batch creation

Transport sends FIFO batches.

Maximum:

64 events per batch

and:

4 MiB serialized body

whichever limit is reached first.

### 35.5 Normal flush cadence

When traffic exists, queued data SHOULD be attempted within approximately:

250 ms

The exact worker wake-up implementation is not part of the public contract.

## 36. HTTP timeout semantics

Each individual HTTP delivery attempt MUST have a maximum total wall-clock timeout of:

1.0 second

Transport timeout MUST NOT propagate to Agent execution.

## 37. Retry semantics

Retryable:

network connection failure
timeout
HTTP 408
HTTP 429
HTTP 500-599

Non-retryable:

HTTP 400-407
HTTP 409-428 except 408
HTTP 430-499 except 429

A batch gets at most:

3 total delivery attempts

Backoff after failed attempts:

attempt 1 → wait 100 ms
attempt 2 → wait 250 ms
attempt 3 → terminal

No persistent retry after the process exits.

After terminal delivery failure:

drop the batch
continue with later queue entries

## 38. Shutdown semantics

AgentLens registers a normal interpreter-exit shutdown hook.

On normal process exit:

1. atomically transition event acceptance from accepting to closed
2. attempt flush
3. use maximum shutdown budget of 2 seconds
4. drop remaining events after the deadline
5. allow process exit

An enqueue that linearizes before the accepting-to-closed transition MAY be accepted. An enqueue that linearizes after that transition is dropped without failing Agent execution.

The shutdown flush cutoff is the final accepted FIFO position at that transition.

AgentLens MUST NOT indefinitely delay interpreter shutdown.

Abnormal termination such as:

* SIGKILL
* process crash
* machine power loss

does not guarantee telemetry delivery.

## 50. DELETE /api/v1/traces/{trace_id}

Successful delete:

204 No Content

Deletion MUST be transactional.

Deleting a nonexistent trace also returns:

### 50.1 Ingest after deletion

Trace deletion removes currently persisted AgentLens state. It is not a permanent suppression rule.

v0.1 has no tombstone, deleted-trace registry, or future-ingest blocklist.

Deletion removes the Trace, matching Spans, matching span_io, and associated ingest_events in one transaction.

After successful deletion, the collector retains no idempotency history for those deleted events. A subsequent event for the same canonical trace_id is processed as ordinary new ingest.

Consequences:

1. A later trace.started or trace.ended MAY recreate the deleted Trace.
2. A later Span event MAY recreate persisted Span state under the span-before-trace rule.
3. An event_id removed with the deleted Trace MAY be accepted again.
4. DELETE does not cancel already queued SDK telemetry.
5. A Trace MAY reappear if deletion races with delayed/retried delivery.

This behavior is deliberate. Preventing recreation requires tombstone semantics and is Deferred.

on_trace_start

Canonical:

    AgentLens canonical ID obtained from native→canonical map
name:
    OpenAI trace.name

    adapter callback UTC time
ended_at:
    null

    OpenAI trace.trace_id

For the supported OpenAI TracingProcessor contract, on_trace_end alone is not success evidence and therefore maps to unset.

## 65. local_only integration semantics

Public API:

agentlens.integrations.openai_agents.install(
    *,
    local_only: bool = True,
)

OpenAI Agents SDK currently supports adding a tracing processor while keeping current exporters, or replacing the current processor set. (OpenAI GitHub)

### 65.1 local_only=True

AgentLens MUST replace the OpenAI Agents SDK global tracing processor list with:

AgentLensOpenAIProcessor only

Equivalent semantic operation:

set_trace_processors([agentlens_processor])

Consequences:

* existing OpenAI trace exporter no longer receives subsequent traces
* existing third-party processors are also removed
* AgentLens is the only active processor in that global OpenAI tracing provider

This behavior MUST be documented clearly.

AgentLens MUST NOT globally disable OpenAI tracing, because doing so would also prevent AgentLens from receiving callbacks.

### 65.2 local_only=False

AgentLens MUST add its processor without replacing current processors.

Existing processors remain active.

Therefore AgentLens provides no guarantee that another configured processor will not export the same framework trace remotely.

The documentation MUST explicitly state this.

### 65.3 Installation idempotency

Calling install() repeatedly with the same mode:

no-op

It MUST NOT register duplicate AgentLens processors.

Calling it again with a different local_only value in the same process:

raise AgentLensConfigurationError

v0.1 does not implement dynamic processor-mode switching or uninstall/restore.

Installation has atomic observable states:

uninstalled
installed(local_only=true)
installed(local_only=false)

A same-mode concurrent install results in exactly one AgentLens processor installation and no-op success for the other call.

For different-mode concurrent installs, exactly one mode is installed and the other call raises AgentLensConfigurationError.

Framework callbacks observe either the complete pre-install processor state or the complete post-install processor state, never a partially modified processor collection.

No concurrency-related AgentLens failure may propagate through a framework callback into Agent execution.

### 65.4 AgentLens disabled state

Calling install() does not automatically set:

agentlens.enabled = true

When installed while AgentLens is disabled, its processor remains functionally no-op for AgentLens event creation.

However, local_only=True still has its documented processor-replacement semantics because calling install() is an explicit integration action.

* change canonical IDs
* change Canonical Span types
* change the Details discriminated union solely to mirror an upstream type

Framework version information remains data under source.framework_version and does not define Canonical Schema compatibility.

## 74. Frozen

The following are Frozen v0.1 contracts.

Changing any requires an explicit specification revision rather than an implementation decision.

Canonical

* Trace shape
* Span shape
* Details discriminated union
* Span type enum
* status enum
* CaptureInfo semantics
* canonical timestamp semantics
* canonical ID format
* framework/native ID separation
* (trace_id, span_id) Span identity
* (native_trace_id, native_span_id) adapter mapping identity
* latency as derived data
* Trace status as observed top-level workflow outcome
* child Span errors do not mutate Trace status

Privacy

* AgentLens disabled by default
* content disabled by default
* secret redaction before transport
* mandatory redaction key set
* no known API keys persisted
* 256 KiB per-content limit
* no partial content truncation
* exact CaptureInfo precedence
* structured-key redaction and free-text sanitization are distinct
* recognizable Bearer, Basic, and credential-assignment patterns are sanitized
* arbitrary unknown-secret detection is not guaranteed

Ingest

* four event types
* full snapshots
* batch envelope
* event UUID semantics
* retry reuses Event ID
* atomic batch
* idempotency
* duplicate rules
* conflict rules
* out-of-order rules
* lifecycle monotonicity
* event-content hash material is event_type + emitted_at_us + canonical payload
* Event-ID idempotency and entity semantic equality are distinct
* Span I/O observation-preserving merge
* non-I/O full-snapshot completeness
* ephemeral carry-forward state is sanitized, memory-only, and per-Span
* individual event limit is server-enforced atomically

Transport

* bounded in-memory queue
* queue size 2048
* non-blocking enqueue
* drop newest
* max batch 64
* max request 4 MiB
* max individual event 1 MiB
* 1-second attempt timeout
* 3 attempts
* retry status classes
* backoff
* no persistent spool
* 2-second shutdown budget
* enqueue, flush cutoff, and shutdown acceptance linearization

Persistence

* SQLite
* table responsibilities
* composite Span primary key
* migration direction
* transactional ingest/delete
* newer-DB refusal

OpenAI integration

* TracingProcessor integration
* exact SpanData mapping categories
* fallback custom mapping
* no fabricated Tool call ID
* no model-name provider guessing
* native ID map
* native Span map is native-Trace-scoped
* Generation request_parameters allowlist/exclusion mapping
* terminal callback without observed outcome maps Trace status to unset
* local_only=True replaces processors
* local_only=False adds processor
* installation idempotency
* concurrent installation linearization

API

* Python public API
* /api/v1 routes
* query request semantics
* query response semantics
* error status semantics

Architecture

* framework adapters separated
* collector framework-agnostic
* UI API-only
* local-first
* tracing failure non-fatal
* localhost-first server
* runtime-enforced loopback HTTP endpoint
* concurrent execution-context isolation
* nested manual Traces are independent and restore outer context
* configure/first-event linearization
* DELETE creates no tombstone and later ingest may recreate a Trace
* MIT license
* declared tested/supported OpenAI Agents SDK dependency range

## 77. Final rule for implementation Agents

When implementation code has multiple possible behaviors:

1. check Frozen
2. check the relevant schema/API section
3. check Issue Definition of Done
4. check architectural invariants

If a behavior is defined there:

implement it exactly

If it appears under Deferred:

do not implement it

If it appears under Implementation Choice:

choose the simplest maintainable implementation

If a required behavior is genuinely absent from all three:

do not silently create a new public contract

Prefer the smallest internal implementation that preserves all Frozen behavior.

## 78. v0.1 design principle

The v0.1 architecture is intentionally:

Framework
    ↓
Integration Adapter
    ↓
Canonical Trace Events
    ↓
Bounded Local Transport
    ↓
Collector
    ↓
SQLite
    ↓
Query API
    ↓
UI

The Canonical Trace Model is the stable boundary.

Framework objects stop at the Adapter.

SQLite stops at the Backend.

Backend persistence stops at the Query API.

The UI sees only Canonical AgentLens data.

v0.1 does not attempt to solve future Agent observability problems.

It establishes one small contract that can survive them.

# TraceMotive v0.4 release gate

Status: final hard gate. A date, review score, or completed issue cannot
override a failed item below. No tag, push, publication, or PyPI upload is
authorized by this document.

## 1. Gate result vocabulary

- PASS: reproducible evidence exists in the release candidate.
- CONDITIONAL: the item has a separate GO gate. For LangGraph, GO includes all
  runtime, security, documentation, and dogfood checks; otherwise it is
  deferred to v0.4.1 and absent from the v0.4 support claim.
- BLOCKED: stop release; preserve the failing evidence and open/fix the issue.
- NOT RUN: never equivalent to pass.

## 2. Fresh-checkout and artifact gates

### G1 — tracked-file-only source

Create the test source from `git archive` or an allowlisted tracked-file copy.
Verify that generated ignored assets such as `frontend/dist/` and
`tracemotive/ui/index.html` are absent before bootstrap.

### G2 — one bootstrap path

Run the documented root command from a clean checkout. It MUST install the
frontend dependencies and run the package build. Record Node/npm versions and
the generated asset manifest.

### G3 — build artifacts

Build sdist and wheel with the project release toolchain. Inspect:

- package version and metadata;
- license file and project URLs;
- UI index and JS/CSS assets;
- absence of source checkout paths, credentials, test fixtures, and raw
  generated secrets; and
- deterministic file list and hashes for repeated builds where supported.

### G4 — installed-user independence

Install the wheel with the declared server extra in an environment outside the
checkout. Prove that serving and loading the UI do not require Node,
`frontend/dist`, or the source tree.

### G5 — full local path

From the installed environment:

```text
serve on 127.0.0.1
 -> health check
-> seed default, identified, and uncertain local demo scenarios
 -> query /api/v1
 -> query /api/v2/compare
 -> query /api/v3/compare
 -> query /api/v4/compare under the v0.4 contract decision
 -> load packaged UI
 -> restart against the same SQLite database
 -> query the same traces again
```

The result must prove persistence, comparison, packaged UI delivery, and local
loopback behavior rather than only a successful process start.

## 3. API and determinism gates

### G6 — compatibility

Run the v1, v2, and v3 contract suites before and after enabling v4. Their
response meanings and byte shapes must remain unchanged. Verify Canonical
schema `0.1` and ingest protocol `1` before and after.

### G7 — API decision and shape

Record and enforce the API decision: v4 is required because unchanged v3 plus an
existing detail route cannot provide the operation diff, bounds, no-diff capture
semantics, conservative array fallback, and cockpit actions without changing an
existing contract. Validate every v4 response against the committed
schema/contract tests, including not-found, invalid ID, malformed stored data,
unavailable capture, redacted content, ambiguous groups, missing parent, and
response-size cases. Package version 0.4 alone is never a reason to add an API
version.

### G8 — deterministic output

For the same persisted snapshots, repeated calls and permutations of input
span order, timestamps that are not semantically relevant, and persistence order
must produce the same serialized v4 semantics and ordering.

### G9 — conservative structural diff safety

Prove deterministic object-key sorting, JSON Pointer escaping, `add`/`remove`/
`replace`, null-versus-absent wrappers, no diff for capture-unavailable or
redacted fields, and explicit truncation. Bound depth at 32, visited nodes at
4096, and change records at 256 per finding. Arrays MUST NOT infer identity or
moves; complex arrays may fall back to whole-array replacement. Exercise deep
and broad JSON without recursion failure or unbounded memory growth.

### G10 — read-only behavior

Compare database bytes/row counts and trace timestamps before and after v4
requests. A comparison request must not mutate SQLite, enqueue events, or
change lifecycle state.

## 4. UI and navigation gates

### G11 — minimal cockpit usability

Starting with two traces, a reviewer can select left/right, open comparison,
see the compact selection control, and use the five named sections: `Look here`,
`What changed`, `Evidence`, `Next`, and `What TraceMotive does not know`. The
primary actions are exactly `Open left span`, `Open right span`, and `Full
comparison`. The screen is not a dashboard.

### G12 — deep links

Test valid, malformed, encoded, missing, deleted, and ambiguous trace/span IDs.
No invalid route may fall through to a different trace or span.

### G13 — inert hostile content

Render `<script>`, HTML, CSS, markdown, URL-looking strings, NUL-like input,
large strings, deeply nested data, and secret-like values in names, paths,
evidence, diff values, and reasons. Confirm no execution, navigation, or
external request occurs.

### G14 — clipboard

Approve copying only sanitized evidence and hash-only local references. Denied
clipboard permission must preserve a selectable text fallback. No remote share
URL, token, or upload is produced.

### G15 — empty state and Core demos

In a fresh local database, the UI shows copyable server, identified-demo,
uncertain-demo, and actual-agent instructions. The browser does not execute them
or probe a provider key. A broader demo catalog is optional and cannot delay
cockpit or structured diff.

## 5. Privacy, resilience, and dependency gates

### G16 — privacy

Verify capture is disabled by default, content capture is independently
disabled, sanitizer runs before queue ownership, known credentials are not
persisted, and safe errors do not echo secret-bearing values.

### G17 — localhost

Verify `serve` remains fixed to loopback behavior and rejects `0.0.0.0`, public
addresses, remote URLs, credential-bearing URLs, and invalid ports.

### G18 — storage and resource bounds

Exercise restart, malformed stored Canonical JSON, newer/invalid database
versions, request/event limits, comparison span/record/response caps, and
transaction rollback. Confirm no memory fallback hides a persistent path error.

### G19 — tracing failure isolation

For every claimed adapter, make mapping, callback property, sink, transport,
timeout, and shutdown operations fail. The user agent/graph result and exception
identity must be preserved.

### G20 — dependencies, provenance, and Conditional LangGraph

Inspect lockfiles, declared extras, supported runtime versions, license files,
project URLs, release source, wheel/sdist contents, and reproducible hashes.
OpenAI support must match the actual tested matrix. LangGraph is a v0.4 claim
only if its complete GO gate passes, including real public-runtime evidence and
the dogfood gate; otherwise record v0.4.1 deferral. Do not claim a framework
because a fake object test passed.

## 6. Documentation and trust gates

### G21 — first-run documentation

README's first 30 seconds show problem, example, local demo, integration path,
safety boundary, evaluation scope, limitations, and architecture. Commands are
copyable and match the bootstrap/release path.

### G22 — evaluation honesty

Exact results are labeled with corpus and version. Public wording states only
the current facts: 30 mandatory scenarios, 15 expected confident meaningful
cases, 14 supported investigation starting points, false-confident meaningful
target/result 0, and false-confident starting-point target/result 0. These are
not universal accuracy, causality, or confidence guarantees.

### G23 — history and compatibility

Frozen v0.1 remains visible and unchanged; v0.2/v0.3 proposed documents retain
their labels; the v0.4 design is frozen for implementation while production
adoption remains a separate authorized change; package version and schema
version are not mechanically conflated.

### G24 — maintainer trust

Before any publication authorization, verify project-level ownership, project
URLs, license, security contact, provenance, and maintainer identity strategy.
If a value is not verified, say so rather than filling it with a guessed person
or organization.

### G25 — maintainer dogfood

Run realistic local agent-failure fixtures and require exact results:

- complete repeated-tool count `2 -> 3`: supported group-level cardinality
  change;
- equal-count repeated members with unsafe identity or reordering: uncertain.

“Uncertain or group count only” is a failure of this gate. This is local
maintainer validation, not external user validation.

## 7. Required evidence bundle

The release candidate review must retain:

- clean-checkout commit/archive identifier;
- OS, Python, Node, npm, and dependency versions;
- bootstrap log and generated asset manifest;
- sdist/wheel file list and hashes;
- installed-user full-stack smoke log;
- v1/v2/v3/v4 contract and adversarial test results;
- exact evaluation report and corpus identifier;
- explicit API v3/v4 decision record;
- maintainer dogfood output with the two exact repeated-tool outcomes;
- security review findings and disposition;
- integration runtime matrix and public API references; and
- documentation/metadata diff and final staged path list.

## 8. Current baseline caveat

At design time, the current Python suite ran 343 tests with one packaging setup
error caused by blocked dependency download (`WinError 10013`) and three
release-only skips. This is not a release gate pass. Rerun the artifact and
installed-user gates in a network-permitted environment. Frontend Vite/esbuild
access-denied results in the restricted sandbox likewise require a permitted
runtime rerun.

## 9. Stop-ship conditions

Stop the release if any of these occurs:

- a fresh checkout needs ignored generated assets without running the documented
  bootstrap;
- installed `serve` needs the checkout or Node;
- v1/v2/v3 semantics change unexpectedly;
- a diff or action guesses a repeated member or hides an uncertainty barrier;
- a redacted or capture-unavailable field is presented as a structured diff;
- a complex array is presented with inferred element identity or move semantics;
- captured content executes or leaves the loopback evidence boundary;
- secrets appear in queue, SQLite, artifacts, logs, URLs, or clipboard output;
- a LangGraph v0.4 claim lacks the full GO evidence;
- documentation implies RCA, causality, importance, or universal accuracy; or
- maintainer/package identity is unverified.

## 10. Decision rule

Only a candidate with all Core P0 gates PASS and no stop-ship condition may be
called v0.4 Core release-ready. LangGraph may be included only when C-V04-09 is
GO. If C-V04-09 is not GO, the Core release remains eligible only after the
support claim is removed and the adapter is recorded as deferred to v0.4.1; it
cannot be hidden behind a green Core test run.

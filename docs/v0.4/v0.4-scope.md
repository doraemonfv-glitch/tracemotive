# TraceMotive v0.4 scope

Status: final scope for implementation. No production implementation or release is
authorized by this document.

## 1. Product decision

TraceMotive v0.4 Core is a small evidence-navigation release: it makes observed
differences, uncertainty barriers, and bounded structured evidence easier to
inspect while preserving the v0.3 “not a diagnosis” boundary. It is not a
dashboard and does not make ecosystem expansion a Core dependency.

The release succeeds when a new user can, from a fresh checkout or installed
artifact:

1. build and package the UI using one documented path;
2. run a local API-key-free demo;
3. select two traces without losing context;
4. navigate from an investigation finding to the left span, right span, or full
   comparison;
5. inspect a deterministic bounded JSON diff and optional secondary copy
   actions; and
6. understand the limits, privacy boundary, and exact evaluation scope.

This is not a causal-debugging proof release. It does not identify a root cause,
assign importance or confidence, or claim that an observed difference caused a
later outcome.

## 2. Priority scope

Product priority is, in order: cockpit > structured diff > onboarding > demo
breadth > ecosystem expansion. Build/bootstrap work is an implementation
prerequisite, not a reason to enlarge the product surface.

### P0: required for the v0.4 release candidate

| ID | Scope | Required outcome |
|---|---|---|
| V04-01 | Fresh-checkout bootstrap | One cross-platform repository command performs frontend install, build, and package; README, CONTRIBUTING, CI, and tests use it. |
| V04-02 | Packaging and installed smoke | A tracked-file-only fresh checkout E2E proves build, wheel/sdist packaging, installed serve, local demo seed, Query API, and packaged UI independence. |
| V04-03 | Minimal investigation cockpit | Provide only Look here, What changed, Evidence, Next, and What TraceMotive does not know, with primary left-span, right-span, and full-comparison actions. |
| V04-04 | Conservative structured diff | Provide deterministic object-key diff, JSON Pointer paths, add/remove/replace records, bounded depth/nodes/records, and conservative array fallback. |
| V04-05 | Empty-state onboarding | Add API-key-free demo and actual-agent instructions with copyable commands; browser never executes commands. |
| V04-06 | Small realistic demo coverage | Keep the default pair stable and add deterministic identified and uncertain scenarios. A broader catalog is optional and must not delay the cockpit or diff. |
| V04-07 | README, evaluation, and spec layering | Reorder README for first-run comprehension; publish exact corpus-scoped evaluation results, limitations, version matrix, security boundary, and v0.1/v0.4 layering. |
| V04-08 | Maintainer dogfood and hard release gate | Run realistic local agent-failure scenarios with exact expected outcomes and require the complete release gate. |

### Conditional v0.4: only with a full GO gate

| ID | Scope | GO requirement |
|---|---|---|
| C-V04-09 | LangGraph adapter | Real public-runtime fixture, named version matrix, Canonical boundary, capture-off/redaction tests, malformed/oversized hostile input tests, failure isolation, installed smoke, exact documentation, and the maintainer dogfood outcomes all pass. |

LangGraph is not unconditional P0. If the full GO gate does not pass, the Core
release proceeds without a LangGraph support claim and the adapter is deferred
to v0.4.1. It must not be called first-class, supported, or experimental unless
the exact documented evidence supports that wording.

### P2: explicitly deferred

- OTLP/OpenTelemetry export, distributed tracing, span links, and hosted
  interoperability.
- RCA, causal proof, replay, execution forking, regression generation,
  failure-fingerprint automation, and LLM-generated diagnosis.
- Cloud, authentication, remote collector, multi-user sharing, and a remote
  clipboard/evidence service.
- Automatic repeated-span pairing based on chronology, ordinal position,
  timestamps, or a guessed similarity score.
- Dashboard features, arbitrary metadata search, inferred trace quality,
  good/bad status, ranking, importance, confidence, or causal labels.
- A full demo catalog beyond the identified and uncertain Core scenarios unless
  it is cheap, bounded, and does not delay higher-priority work.
- A new Canonical schema version, ingest protocol version, or storage migration
  solely for v0.4 UI needs.

## 3. Compatibility and versioning decisions

The package version `0.4.0`, if separately approved later, is a distribution
version only. It must not be substituted for any of these compatibility values:

- Canonical schema version: `0.1`.
- Ingest protocol: `1`.
- Existing HTTP v1 collector contract.
- Existing `/api/v1`, `/api/v2`, and `/api/v3` response contracts.

### API v3/v4 decision

Decision: add `/api/v4/compare/{left}/{right}` for v0.4 and keep
`/api/v3/compare/{left}/{right}` unchanged. This is not API versioning because
the package is 0.4. The v0.4 response contract is materially different: it adds
operation-based bounded diff records, explicit no-diff behavior for unavailable
or redacted capture, conservative array fallback, and cockpit action targets.
Adding those fields/semantics to v3 would change its exact response contract;
composing v3 with the existing v2 detail response would not provide the new
contract's bounds and capture semantics. Therefore v4 is justified by a
contract boundary, not by the package version.

## 4. Integration position

OpenAI Agents remains the validated adapter. LangGraph is a Conditional v0.4
item only with the full GO gate; otherwise it is v0.4.1 work. No other framework
receives a support claim by analogy.

OTel interoperability is documentation-level in v0.4: describe a future mapping
from Canonical trace/span identity, timestamps, names, status, and attributes to
OTel concepts without importing OTel objects into the Canonical contract or
shipping an exporter.

## 5. One-cycle feasibility

The Core is feasible as one focused implementation cycle because the current
comparison, divergence, investigation, privacy, serve, and package layers
already provide most of the hard semantics. The highest-risk additions are the
fresh-checkout E2E, safe UI/API evidence projection, and exact repeated-tool
dogfood expectations.

Conditional LangGraph is feasible in the same cycle only if its early public
runtime probe passes and the complete GO gate remains green. Otherwise the Core
must ship without it and the adapter moves to v0.4.1.

## 6. Explicit stop conditions

Stop and return to design if any implementation proposal requires:

- a Canonical schema change to carry UI-only navigation state;
- a framework object to cross the adapter boundary;
- redaction after enqueue or persistence;
- a remote endpoint, authentication, or cloud dependency;
- a diagnosis/causal assertion not represented by direct evidence;
- an implicit pairing of repeated siblings;
- a browser action that executes a command or interprets captured content; or
- an unverified package maintainer identity.

## 7. Success definition

v0.4 Core is successful when the release gate can show a clean fresh-checkout
path, an installed packaged UI, a minimal cockpit with left/right/full
comparison navigation, bounded and redaction-safe structured diff output,
identified and uncertain key-free demos, exact maintainer dogfood outcomes, and
documentation that states both capability and limits without hype. LangGraph is
part of v0.4 only when C-V04-09 is GO; otherwise it is explicitly v0.4.1.

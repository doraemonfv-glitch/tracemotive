# v0.1.1 release readiness

This checklist is local-only. These commands build and inspect artifacts; they
do not upload, publish, create a release, or push a tag.

The Python distribution and import package are both `tracemotive`, with
version `0.1.1`. Public package-index publication remains a separate
maintainer-controlled release action; this checklist validates the local
artifacts and installed runtime under the final pre-release identity.

The declared runtime and optional dependencies are:

- core: `fastapi>=0.110,<1`
- `server`: `uvicorn>=0.30,<1`
- `openai-agents`: `openai-agents>=0.17,<0.18`

Build from a clean checkout. Node.js/npm are release-build dependencies only;
they are not runtime dependencies of an installed wheel:

```text
cd frontend
npm ci
npm test
npm run build:package
cd ..
python -m pip install build
python -m build --sdist --wheel
```

Inspect `dist/` and install the wheel into a new virtual environment from a
temporary working directory, not from the repository root:

```text
python -m venv .venv-check
python -m pip install dist/<wheel-file>.whl
python -c "import tracemotive; print(tracemotive.__file__)"
```

The installed path must be in the temporary environment and core import must
work without the `openai-agents` extra. The optional integration may be tested
separately with:

```text
python -m pip install "dist/<wheel-file>.whl[openai-agents,server]"
```

The packaged UI is generated by npm run build:package, which runs the
production Vite build and copies frontend/dist into tracemotive/ui/ before
wheel construction. The installed package exposes that resource boundary via
tracemotive.ui.get_ui_root() and does not require Node.js, npm, Vite, or the
frontend source tree to locate the assets.

With the server extra installed, the packaged local experience is:

```text
tracemotive serve
```

It binds only to 127.0.0.1, uses the persistent database path resolver, and
serves the packaged UI and existing Query/ingest API from the same origin.
The older direct Uvicorn Collector factory command remains available as a
development and v0.1 compatibility path.
